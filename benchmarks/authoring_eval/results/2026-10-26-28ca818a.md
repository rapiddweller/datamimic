Models: Haiku and Sonnet. One run for each model and case (10 runs). Opus is not run yet. This pilot checks the method and the cost. It is too small for a rate.

## Void runs

The audit finds a write outside the run directory in `haiku-e02` and `haiku-e05`. Both agents named the breach themselves. They do not count. Repeat them with new agents.

## Flags reviewed by hand

The audit flags the path of the run directory itself in three Sonnet runs (e02, e03, e05). The agent set `D=<run directory>` and then used `$D/work` and `$D/venv`. The tool call reads and writes only inside `work` and the venv. The audit does not resolve variables. It also reads `//` in a heredoc as a path. Both are audit false positives.

## Why the first Build was rejected

| Cause | Runs |
|---|---|
| Total row budget exceeded: the default `max_count` is 10 and counts all products together; the message names no numbers (#414, item 3) | haiku-e02, sonnet-e02, sonnet-e03 |
| `range` expectation: the agent wrote `min`/`max`, the schema wants `minimum`/`maximum` | haiku-e01, haiku-e05 |
| `per_parent_count`: wrong shape of the `subject` | haiku-e03 |
| Expectation names an unknown field | sonnet-e01 |
| Attribute absent from the runtime model (DM103) | sonnet-e05 |

Every agent recovered after one or two Builds, and none used more than 34 tool calls (limit 40).

## Cost

About 80,000 to 120,000 tokens for each run. A full campaign of 5 runs for each model and case is 75 runs, about 7 million tokens.

## Limits of this pilot

- One run for each cell: no rate can be computed.
- The sub-agents may have loaded the project instructions of the session. The audit found no read of `AGENTS.md`.
  Later evidence: a sub-agent of a session has `AGENTS.md`, `CLAUDE.md` and the memory in its context. These runs were not blind. The protocol now uses `run_subject.py`.
- The oracle ran from the checkout of `28ca818a` with the `benchmarks` directory of the eval branch.
