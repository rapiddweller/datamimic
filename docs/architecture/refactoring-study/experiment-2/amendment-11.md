# Amendment 11: declare the existing Authoring boundary shape

Date: 2026-09-23

## Decision

Allow only the four exact JSON-map positions returned by `run` and `scaffold`. Expose
`datamimic_ce.authoring.spec:LeafFieldKind` as the single additional public alias used by the
Authoring contract types; the rest of `spec` stays private.

These map fields are already part of the public response shape: product samples and corrected
fragments are keyed JSON objects, and per-parent observations are keyed integer counts. Their
contents are dynamic data values, not authoring implementation types. The exceptions identify the
exact facade function, returned field path, and annotation; all other boundary types remain
checked.

`LeafFieldKind` is referenced by public Authoring contract types. Naming only this finite alias
preserves that type reference without exposing the `spec` module as a whole.

## Evidence

- `datamimic_ce.authoring.api.run` and `scaffold` return the product samples, repair fragments,
  and acceptance results through `RunResult` and `ScaffoldResult`.
- `datamimic_ce.authoring.contracts` defines `ProductResult.sample` and
  `ReplaceFieldRepair.corrected_fragment` as `dict[str, JsonValue]`, and
  `PerParentCountAcceptanceResult.observed_counts` as `dict[str, int] | None`.
- The exact four positions are recorded by `AUTHORING-API-TYPES`; ArchKeel reports one
  `boundary_type_allowance` FACT for each position.
- The contract declares schema version `2.1.0`. The `$schema` URI pointed at ArchKeel `0.6.0`,
  whose contract schema is also 2.1.0 but rejects `allowed_positions` because the rule schema sets
  `additionalProperties: false`. The URI is removed until a published schema accepts that field;
  restore a versioned URI then.
- The digest-generation checker was ArchKeel `0.46.0` at OID
  `44a4efc81a9e87c06134aad24486dca38471e9a3`; final validation used `0.46.0` at OID
  `f244ae3a637fefcbfe04bb818b23a6de07025cdc`.
- Canonical before/after contract digests are in `amendments/amendment-11.json`, generated by
  `archkeel validate --against fc4cee0638e51690106c5e23557ebc89ae0ae705 --write-amendment`.
- The direct scan has complete coverage, zero rule violations, and four allowance FACTs. Its 20
  raw UNKNOWN records are identical to a control scan of the unamended `fc4cee0` checkout with the
  same checker: 10 `boundary_type_position`, 5 `boundary_type_limit`, 1
  `context_alias_limit`, 3 `private_attribute_access_limit`, and 1 `dynamic_call_limit`. The four
  Authoring-rule UNKNOWN records are also unchanged; `unknown_positions=0` and `declared_rules`
  is `PASS`.
- `--against` accepts the amendment. Validation still exits 1 solely because the frozen baseline
  records four resolved `NO-MAGIC-CONTROL-FLOW` findings. The final checker excludes allowance
  FACTs from `typing_positions`, which remains at the frozen value of 144. `known-violations.json`
  remains untouched.
