# DATAMIMIC CE 5.0 — unreleased

Tracks [#335](https://github.com/rapiddweller/datamimic/issues/335).
PyPI currently contains 4.3.0; the new authoring interface requires this source
checkout. Package versions remain derived from Git tags. Build protocol `4.0`
is independent of the CE package version.

## Breaking changes

- Python minimum becomes 3.11. Python 3.10 compatibility shims are removed.
- XML is the persisted executable project; DM JSON is transient.
- `BuildRequestV4` replaces persisted Intent/Scaffold authoring. Expectations,
  roles and verification options belong to the transaction.
- Root scaffold/lint/dry-run/reference/capabilities commands move to the typed
  `datamimic authoring` subtree. Legacy Python authoring modules are retired.
- Catalog-backed errors carry stable identity and repair guidance. Some formerly
  generic exceptions now use portable typed exceptions with their native cause.

Follow the [one-time migration](../migrations/authoring-errors.md), retaining
original input and separate verification requirements. Existing XML execution is
supported. Compile support, bounded-proof eligibility and real external delivery
remain distinct; arbitrary Python execution cannot be made safe by target isolation.

## Agent entry point

The [Codex / Claude Code plugin](../agent_plugin.md) carries the consumer workflow
into other repositories. One skill uses the existing CE CLI/optional MCP adapter
or the Platform project's server-owned MCP workflow. The runtime's live contracts
remain authoritative.

## Release gates

- [ ] Reconcile relevant open issues against the exact candidate; document limits.
- [ ] Local lint/typecheck, authoring/transport tests and architecture gates pass
  with retained UNKNOWNs and unchanged approved limits.
- [ ] Wheel and sdist build; isolated installed-wheel checks pass with and without MCP.
- [ ] Native Codex and Claude installation, skill selection and complex workflows
  pass outside this repository, including repair and independent acceptance checks.
- [ ] Publish the separately inspected plugin ZIP as its own release artifact.
- [ ] Independent branch review and complete CI pass on the exact release commit.
- [ ] Obtain release approval, update preview installation text, tag `5.0.0` and
  let the existing tag workflow publish the verified Python artifacts.
- [ ] Fresh `pip install "datamimic-ce==5.0.0"` and plugin installation from that
  tag pass; verify PyPI metadata/README and public client guidance.

Until those gates are recorded, this document describes preparation, not a
published 5.0 release. Repository installation does not imply approval or listing
in a public plugin directory.
