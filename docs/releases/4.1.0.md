# DATAMIMIC CE 4.1.0

DATAMIMIC CE 4.1.0 focuses on agent authoring, deterministic source selection,
runtime ownership boundaries, and Python 3.10 compatibility. These notes describe
the changes since 4.0.1.

## Highlights

- Added the typed `model.dm.json` authoring workflow: progressive reference queries,
  deterministic compilation, bounded execution, acceptance checks, and verification
  in one scaffold transaction.
- Added compiler-derived facts and structured repair guidance for nested foreign keys,
  memstore pipelines, time-series dimensions, source products, and acceptance limits.
- Centralized source loading, routing, pagination, cyclic selection, and distribution
  policy in the data-source boundary instead of task-specific implementations.
- Added atomic extension registration so an element definition and its constraint
  contract cannot be observed in a partially registered state.
- Hardened XML parsing against DTD and entity expansion in both runtime descriptors
  and authoring input.
- Restored verified Python 3.10 support and added Python 3.10/3.11 release checks.

## Agent and transport changes

The optional MCP adapter now exposes exactly four tools backed by the canonical
authoring service:

| MCP tool | CLI equivalent |
|---|---|
| `datamimic_reference` | `datamimic reference` |
| `datamimic_scaffold` | `datamimic scaffold` |
| `datamimic_check` | `datamimic lint` |
| `datamimic_run` | `datamimic dry-run` |

This intentionally replaces the earlier MCP-only domain generators, resources,
recipes, and `list_domains` surface. Tool input is carried in the typed `request`
object. MCP requests reject unknown fields and coercive safety flags.

The obsolete `validate` CLI alias is removed; use `datamimic lint`. The obsolete
`response_format` request field is also removed because result presentation belongs
to the CLI or MCP transport boundary.

## Runtime and compatibility

- DataSourceRegistry is the single routing owner used by Generate, Variable,
  NestedKey, and Reference execution paths.
- Committed DATAMIMIC XML matrices cover local data sources and references across
  distributions, pagination, cyclic/unique selection, and seeded replay. External
  matrices retain MongoDB, PostgreSQL, MSSQL, and Oracle coverage.
- MySQL-backed `SequenceTableGenerator` runs single-process only. PostgreSQL retains
  native-sequence multiprocessing support.
- Database sequence and table identifiers are quoted using the active SQLAlchemy
  dialect.
- The package includes `py.typed`, correct MIT license metadata, and imports on
  Python 3.10 and newer.

## Migration checklist

1. Replace `datamimic validate ...` with `datamimic lint ...`.
2. Replace removed MCP domain/resource calls with the Python/CLI domain facade or
   one of the four canonical authoring tools.
3. Send MCP payloads under `request` and remove `response_format`.
4. Use strict JSON booleans for safety options such as `allow_side_effects`.
5. Set `numProcess="1"` for MySQL descriptors using `SequenceTableGenerator`.

Existing XML descriptors remain supported. The recommended workflow for new models
is to keep business intent in `model.dm.json` and treat compiled XML as runtime output.
